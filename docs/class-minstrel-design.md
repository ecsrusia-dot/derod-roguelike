## 0. 배경 — v1 → v2 변경 사유

v1에서 **음표·코드 시스템 (옵션 A)** 으로 설계했으나, PM이 v1을 보고 다음 4가지 결정을 내림:

| # | v1 (폐기) | v2 (채택) |
|---|---|---|
| 1 | 음표(0~7) 신규 자원 + 임계 발동 2/3/5/7 | **자원 시스템 신설 X.** 액티브는 **에테르 (cost 0~3) + 쿨다운 (cd 0~3)**, 소울은 **소울 게이지 0~100** (5직업과 동일) |
| 2 | 차별화 = 음표 임계 콤보 | **차별화 = 직업 전용 패시브 7종 + 메인 스탯 매력** (자원이 아닌 *패시브 효과·스탯 시너지*로 정체성 확보) |
| 3 | 메인 스탯 미정 (지능 또는 매력 또는 음악성 신규) | **메인 스탯 = 매력**. 사제와 매력 메인 겹침 → 시작 매력값 PM 결정 필요 (priest 19와 비교) |
| 4 | 데미지 타입: sonic 신규 (옵션 1중) | **sonic 신규 채택 동의**. 기존 physical/magic/defense/buff에 추가. 매력 시그니처에 sonic 데미지 증가 로직 추가 필요 |

→ **음표 시스템 폐기로 1.51.0 인프라 PR이 단순화됨** (자원 시스템 코드 0줄 추가). 5직업 동일 패턴 안에서 *직업 전용 패시브 7종 + sonic 타입 + 매력 시너지*로 정체성 확보.

## 7. 매력 시그니처 sonic 데미지 추가 단계 (PM 결정 필요)

기존 매력 시그니처는 회복·받는 데미지·영혼만 다룸. **sonic 신설에 따라 매력에 sonic 데미지 boost 단계가 필요**. 옵션 3안:

| 옵션 | 효과 | 임계 | 작동 직업 | 추천 |
|---|---|---|---|---|
| **A. 신규 3단계 임계 + 5단위 누진 (추천)** | sonic 데미지 +5% / +10% / +15% | 매력 **14+** (3단계) → 14~18 +5% / 19~23 +10% / 24+ +15% | 모든 직업 매력 14+ 시 (사제 19·악사 18~ 자동 활성) | ★ 임계로 비악사 직업은 약하게만, 악사는 메인 매력이라 강하게 |
| B. 자동 가산 (임계 없음) | 매력 × 0.3% (매력 10 → +3% / 매력 19 → +5.7%) | 없음 | 모든 직업 자동 | 균등하나 차별화 약함 |
| C. 직업 ID 한정 (악사·사제만) | 매력 시그 3단계 = sonic +N% (악사·사제만 활성) | 매력 14+ + 직업 = `minstrel` or `priest` | 악사·사제만 | 가장 안전하나 시그 시스템 일관성 깨짐 (4스탯 자동 가산 패턴과 어긋남) |

→ **추천 A**. 1.40.0~ 시그니처 시스템과 일관 (임계 + 5단위 누진). 비악사 직업은 매력 메인이 아니라 시그 활성이 어려워 자동으로 사제·악사만 강함.

### 7.1 옵션 A 구현 가이드 (확정 시)

```js
// src/utils/helpers.js — 매력 시그니처 3단계 신규
// 매력 → sonic 데미지 보너스 (%). 매력 14+ 시 발동, 5단위마다 +5% 누진
//   14~18 → +5% / 19~23 → +10% / 24~28 → +15% / ...
export function calcChaSig3Sonic(stats) {
  if (!stats || !stats.매력 || stats.매력 < 14) return 0;
  return (Math.floor((stats.매력 - 14) / 5) + 1) * 5;
}
```

`damage.js`의 `calculateDamage` 안에서 `type === 'sonic'`일 때 `(1 + calcChaSig3Sonic(stats) / 100)` 곱셈. StatusPanel의 「sonic 데미지 보너스」 합산 라인에도 1줄 추가.
